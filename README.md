## 🔍 Deep Dive: Phase 3 - The Payment Engine

This is the most complex phase, involving on-chain interactions and background processing.

### Key Features Implemented:
- **Invoice Generation:** `POST /api/invoice` creates a unique reference (Memo) for the transaction.
- **The Watcher (Background Worker):** A Go routine that:
    1. Monitors the merchant wallet's incoming transactions.
    2. Decodes transaction logs to find the specific "Memo" string generated by the invoice.
    3. Verifies the amount and currency (USDC).
    4. Updates the DB status to `PAID`.
- **Frontend Polling:** The frontend repeatedly checks the invoice status to auto-unlock the screen without refreshing.

### Technical Highlights:
- **Atomic Transactions:** Frontend constructs a transaction with two instructions: `Transfer` (USDC) and `Memo` (Identifier).
- **Concurrency:** The Watcher runs concurrently with the API server using Go routines.
